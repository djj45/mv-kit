# 独立交付验包

```sh
uv run tools/verify_package.py /path/to/delivery-package
uv run tools/verify_package.py /path/to/delivery-package --out /tmp/package-verification.json
```

输入是包含 `manifest.json` 的整个交付目录。命令不加载原工程，不读取回执、QA 或音轨元数据里保留的原机器绝对路径，只检查包内相对路径。需要 Python 项目依赖及 FFmpeg / FFprobe，可以在另一台安装了 mv-kit 的电脑运行。

默认向标准输出打印 JSON；`--out` 写一个新报告文件，拒绝覆盖已有文件。退出码 0 表示包内完整性与规格通过，1 表示检查失败；命令参数或报告输出错误返回 2。

检查内容：

- manifest 声明的文件是否存在，字节数与 SHA-256 是否匹配；成片、回执、字幕、QA、镜头、独立轨和混音参考等必需文件是否被列入清单。
- 成片实际解码帧数、帧率、尺寸、时长和音频存在性，及其与回执的一致性。
- 镜头帧区间是否从 0 连续覆盖到总帧数，是否有缺口、重叠、重复文件引用；逐镜实际帧数、帧率、尺寸和时长是否匹配。
- 独立轨与参考混音是否为全片等长的 48 kHz stereo float PCM。
- 字幕是否落在成片范围内，SRT / VTT 是否与 manifest 中的字幕一致。合法重叠字幕仍由原有字幕 QA 提示，不当作传输损坏。
- 包内 QA 状态是否与 manifest 相符；附带人工审片记录时，检查其完整版本绑定、镜头覆盖和整体结论。

相对路径必须留在包内，拒绝 `..`、绝对路径及符号链接。不会沿源文件路径访问原素材。新包包含 README 摘要；旧版 v1 包仍可验包，没有人工记录时保持 `pending`。额外的未列入清单文件不属于已验证内容。

`status: pass` 只表示验包范围内通过。报告另列原有 `qa` 与 `humanReview`；自动 QA 的警告、未验证项仍保留，验包也不会将待审片状态改为通过。该命令不重新判断叙事、审美、旁白内容，也不认证记录里填写的审片人身份。

## 随包附带人工审片记录

在新版审片页逐镜复核并导出 JSON，再执行：

```sh
uv run tools/render.py projects/my-song package --review-record /path/to/review-record.json
```

画面、声音、字幕与渲染回执都必须匹配；仅改字幕、MP4 未改变时，旧人工记录同样不能沿用。记录保存在交付包的 `review-record.json`，其摘要进入 manifest。未传入该参数时，交付包继续标记为待人工复核。

验包回归覆盖移除原工程后的独立运行、文件缺失和损坏、帧区间缺口、错时长音轨、字幕越界、越界路径、符号链接、旧版本记录和无记录的虚假通过状态。120 镜头完整交付回归也调用此命令背后的同一校验实现。

第十一批记录可携带比较摘要 `snapshot` 和历史参考 `references`。新版打包与验包会保留这些字段，并检查参考目标属于当前镜头；历史参考本身不代表当前版本已获批准。旧记录没有这些可选字段时仍可按原规则校验。

第十四批支持带时间标注的版本 2 审片记录（`issues` 与历史 `references[].issues`），版本 1 继续兼容。打包与验包用实际渲染回执校验输出帧时钟、标注范围、起始帧镜头身份，并检查未复核问题不能与相关镜头／整片通过结论并存。已修改不等于已复核；历史问题只保留参考。含时间标注的记录不能降为版本 1 交给旧工具，详见 [REVIEW.md](REVIEW.md)。
