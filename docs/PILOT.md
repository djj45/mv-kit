# 代表性动态样片

在扩展整片之前做一段能播放、带实际音乐的样片。选择最能暴露风险的部分：代表性画风、关键动作或歌词排版，加上至少一次镜头衔接；不能默认选最容易的开场。通常 3–6 秒，复杂阅读可放宽到 10 秒。区间必须包含动作预备、落点及足够停留，不能只截最漂亮的一帧附近。

## 制作与交付

1. 在 `TREATMENT.md` 写选择理由、涉及镜头 / 配方、关键拍点和要验证的问题。先出定调帧确认构图。
2. 实现这几个镜头和衔接，局部 `check / qa` 检查代码、文字、主体和阅读顺序。样片使用正式项目的时间线和素材，不另写一套预览动画。
3. 导出并全速带声音播放，检查运动快慢、动作落点、文字可读时间、衔接和音乐关系。关键动作仍可用 `strip` 看逐帧。
4. 交付可播放 MP4，附上区间、选择理由和尚待确认的问题。静帧 / 拼板不代替动态样片。用户要求先审样时等待反馈；用户已经要求直接完成时自行审看后继续，不额外增加审批关卡。
5. 确定可复用的时序和风格后再扩展全片。改了主体画风、字体或核心动作，就重新做对应样片。

```sh
uv run tools/render.py projects/X check
uv run tools/render.py projects/X qa --from 30 --to 36
uv run tools/render.py projects/X pilot --from 30 --to 36
# 快速动态草稿可加 --preset veryfast；清晰度验收保留最终规格
```

把选定区间存入 `project.js` 后可以直接运行 `pilot`：

```json
"pilot": {
  "from": 30,
  "to": 36,
  "reason": "副歌关键动作 + 同形转场；检查大字阅读时间与重拍落点"
}
```

这里的时间为歌曲绝对秒数。先从已经按歌词 / 节拍解析的时间线读取，再填入样片范围。歌曲或剪辑变化后重选；它不改变正式时间线。CLI 的 `--from / --to` 必须成对提供，并完整覆盖配置中的范围选择。

## 输出约定

- 默认 `out/pilots/pilot-<起>-<止>.mp4`，不会覆盖整片默认输出。相同范围再次导出会替换该范围的样片；要留版本用 `--out out/pilots/v2.mp4`，不同分辨率也可另命名。
- 同名 JSON 记录实际起止、帧数、尺寸、镜头、音频与主要编码参数，状态是 `rendered`、审看待完成。它不是音画同步证明，也不是质量检查通过记录。
- 仍用现有分块缓存、浏览器逐帧渲染、运动模糊和 FFmpeg 封装。支持 `--fps / --samples / --4k / --workers` 等原有参数。
- 默认要求项目音频存在；纯动作研究明确使用 `--noaudio`，交付时标注静音，不宣称音画已验证。默认没有专门给样片增加审批步骤。
- 拒绝越界、非有限或空区间；尾点按输出帧数取整并记录。只包含一个镜头会提示补看衔接，不强制每个单镜练习跨镜。
- 渲染出错时失败退出，封装成功后才替换样片。整片导出仍使用原命令，`pilot` 不改变项目的 `from/to`。

## 审看记录（写在 TREATMENT 内）

记录样片文件、实际区间、局部 QA 错误 / 警告、全速带声音看过的结果，以及仍未解决的问题。视觉方案可用不等于整片完成：最终交付继续执行整片 `check / qa`。示例见 [recipe-demo](../projects/recipe-demo/README.md)。

## 样片的编码后检查

`pilot --verify` 在导出后运行 [filmcheck / sync](ENCODED-QA.md)。也可用 `--file` 单独检查已导出的样片。除审样 `.json` 外，每次导出另写 `.mp4.render.json` 作为版本与规格回执；样片范围内无事件时同步结果是 `unverified`，不代表样片出错或全片音画已验证。
