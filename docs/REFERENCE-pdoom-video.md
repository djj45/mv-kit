## 0. 一句话

**他统一的是「色」，变化的是「体裁」；我们反过来——统一的是「体裁」（lumen 的点云 + 细线），变化的是「色」。**

- 参考片：一套全局命名调色板（9 个键，中性灰阶 + 一个信号橙 + 一个只属于 2 秒的稀有强调色），画面变奏靠**体裁**（版画、示波器、公文纸、钞票纹、蓝图、光线步进 3D、织物、UI）和**明度反转**（黑底 ↔ 米白纸底）。40 个场景模块共用一套色、一套字体、一套颗粒。
- 本片：45 个镜头用了 4 套调色板（`ember` 17 / `rose` 14 / `ice` 8 / `alert` 6），画面变奏靠**换色相**；而画法始终是同一种（点云 + 细线 + 四角遥测 + 一行字幕）。于是"花"和"闷"同时出现：颜色换了四族，画法却只有一种。

量化证据（逐帧实测；A 侧是参考片自己的 14 张剧照，B 侧抽了两组：与剧照**同刻**的 14 帧，和**全片均匀**抽的 19 帧）：

| 指标 | 参考片 A | 本片 B（均匀） | 本片 B（同刻） |
|---|---|---|---|
| 全片平均色相的圆标准差（越小越"一个色"） | **5.4°** | **69°** | 67.6° |
| 有颜色的像素里，落在信号橙 ±25° 内的比例（池化） | **85%** | 23–28% | 16% |
| 全片池化色相集中度 R | **0.85** | 0.46 | 0.27 |
| **单帧之内**的色相集中度 R（两边几乎一样） | 0.83 | 0.84 | — |
| 高光占比（luma > 0.75） | **17%** | **0.3%** | 0.4% |
| 近黑占比（luma < 0.06） | 38–43% | **72%** | 74% |
| 每帧归一化边缘密度 | **0.0166** | 0.0101 | — |
| 每帧纹理覆盖 / 元素墨覆盖 | **15% / 3.1%** | 8% / 1.6% | — |
| 平坦区（与亮度无关） | 61% | **78%** | — |
| 细颗粒独立元素数（1920） | 335 ± 297 | **442 ± 426** | — |
| 粗颗粒重元素数 | **113** | 96 | — |

两件反直觉的事：

1. **本片不是"每帧花"，而是"帧与帧之间换色"。** 单帧之内的色相集中度和参考片几乎相同（0.84 vs 0.83）；差别全在跨帧——参考片全片只有一个色相瓣（15° 占 78%），本片有三个（225° 31% + 15° 29% + 285° 13%，正好对应 `ice`/`ember`/`rose` 三套章节调色板）。所以"统一配色"要的不是"每帧少用色"，而是**全片一个色**。

2. **本片不是"更满"，而是"更空 + 更碎"。** 参考片每帧的墨、边缘、纹理都更多（约 2 倍），本片 78% 是平坦区、72% 是近黑；本片唯一"更多"的是**细小的独立碎点**（442 vs 335，而且粗颗粒尺度上反过来：96 vs 113），每个都又小又暗。**"碎"不等于"满"**——本片缺的不是留白，是**对比度**和**主角的体量**：全片几乎没有高光（0.3%，参考片 17%），最亮的一帧平均亮度只有 0.33，而参考片有整幅米白纸的场景（平均亮度 0.86）。

（口径说明：本片的原始饱和度看起来更高，那是近黑像素的量化噪声；按曝光门控后两边都是 0.27–0.28，反而参考片的彩色像素更饱和。另外参考片这 14 张剧照是 **HUD 关闭** 渲出来的，本片抽帧带着自己的 HUD——这个不对称是**偏向参考片**的，它仍然赢在结构量上。）

## 1. 十二条特征

### 1.1 一套全局命名调色板，色彩是"词汇表"不是"参数"

`app/src/engine/palette.ts` 一共 29 行，9 个键：`ink #0A0A0B` / `ink2 #151517` / `graphite #5E5B57` / `ash #9C978F` / `bone #EEE9DF` / `signal #FF4D12` / `ember #FF8A3D` / `blood #C21D0B` / `acid #D8FF3C`。

- 场景只写 `rgba('signal', .6)` / `LIN.ember`，不写 hex。想换片子的色，改一个文件。
- `signal` 橙是**唯一**的彩色主角（火花、导火索、P(doom)、唱到的词）；`blood` 是它的暗部；`ember` 是它的高光核心。
- `acid #D8FF3C` 是"只属于一个瞬间"的强调色——全片只在吃蘑菇那 2 秒出现（`TREATMENT.md:18`）。**一个色 = 一个记忆点。**
- 明暗节奏靠**反转**：公文、蓝图、图表几场把画面翻成米白纸 + 墨线，"橙色在两种底上都是橙色"（`TREATMENT.md:19`）。

### 1.2 发光是全局阈值，不是自由发挥

`post.ts` 的 bloom 阈值默认 **0.85 linear**，超过就发光。规则写死在风格圣经里（`TREATMENT.md:20`）：

> **只有 signal/ember 可以超过 ~0.85（发光）。bone 字必须始终锐利，绝不发光。**

所以任何一帧里"亮的东西"只有一处——观众的视线没有第二个落脚点。这条是"统一"的物理来源，比调色板本身更狠。

### 1.3 一帧一个主角

每个 plate 有一个能叫出名字的**物件**：独角兽（TikZ 画出）、loss 曲线的峡谷、面具、蛇眼、月亮的钞票纹、7-B 表格、路线图、回形针晶格、燃烧的导火索、无限堆叠的 transformer、笔记本电脑。它是**有体积/有轮廓/有名字**的东西，不是氛围场。

配套的是"家具"：细线刻度、等宽小字标注、引线、脚注、印章——都是**小、少、且属于那个物件**的（"瑞士网格、非对称构图、慷慨的留白、细线规则、大字旁边的小号等宽注解"，`TREATMENT.md:28`）。

> 测量：它的"元素墨覆盖"是本片的约 2 倍（3.1% vs 1.6%），粗颗粒重元素数 113 vs 96；本片只有**细小碎点**更多（442 vs 335）。也就是说本片不是主角太多，是**没有主角**、只剩碎点。

### 1.4 每场一个"预算"：2–4 个 draw call、一个主角

这是它 22 个 plate 里唯一一条从不变形的工程约束（逐场数过）：

| 约束 | 值 |
|---|---|
| 全屏 shader pass | ≤ 5（多数 1–2） |
| GPU `LineBatch` | ≤ 4（`hook` 一场 0 个） |
| Canvas2D 层（文字） | ≤ 2（`leftturn` 一场 0 个，覆盖层直接在 shader 里画） |
| 同屏主角 | **1**（少数"2"是"主角 + 它的注解物"） |
| 共用的调色（bloom 0.2–0.85 / threshold 0.8–1.8 / vignette 0.16–0.6） | 全片一套 |

负空间是写在代码里的：地形从 `vec3 col = C_INK` 开始**只加不铺**（`loss.ts:134`），方格纸只以 1.1%/2.8% 的强度加 bone（`open.ts:67`），hook3 就是"很多黑里的一条极细字"（`hook.ts:417`）。
**变化全部关在主角内部**——不是靠加层、加特效、加密度。

### 1.5 明度纪律：黑要真黑，白要真白

它敢用满 0→1：14 张剧照里有两张是**整幅米白纸**（平均亮度 0.86 / 0.81，高光像素占 88% / 89%），其余的深黑场平均亮度 0.06–0.33；全片高光占比 17%。

本片：均匀抽的 19 帧里高光占比 **0.3%**，平均亮度 0.03–0.13，最亮一帧 0.33，**整片没有一场是亮的**。这就是"看起来闷"的物理原因——不是颜色问题，是**动态范围没用**。

### 1.6 歌词就是画面，且每一版画法都不同

`TREATMENT.md:34`：

> 每张 plate 都用**不同的图形方式**整合歌词：被火花写出来、骑在曲线上、当作 token 打出来、盖在表格上、织进布、做成 `[MASK]`……**词是画面的一部分，不是盖在上面的字幕。**

举例（都在 `TREATMENT.md` 的逐场说明里）：0s 独角兽那场是"火花这支笔把歌词写出来"；`loss` 场是"文字骑在 loss 曲线上"；三个 pre-chorus 是"prompt 输入框里逐 token 打出来，每个 token 上面还闪一下 next-token 概率分布（候选词是笑话：`eat 0.44 · delete 0.21 · train on 0.18`）"；`loom` 场是"逐 token 生成，每个节点叉出暗色备选分支"；`paperclips` 场是"被回形针挤在中间，字宽压到 62"；`fuse` 场是"字沿着导火索排，火花扫过就炭化成灰"。

强调规则（`TREATMENT.md:33,35`）：唱到的部分 `signal`/`bone`，没唱的部分 **30–40% 的 bone**；"允许提前最多 0.4 s 把整句淡淡显出来，但高亮绝不抢在声音前面"。

### 1.7 用构图给字让位，而不是给字加垫底

`TREATMENT.md:120`（Revision 4）原话：

> **不给歌词加暗色垫底（knock-out）**——镜头把笔记本电脑摆在偏右，左边的字落在画面左上的黑里。

这一条正对着我们踩过的坑：本片为了歌词可读，先加过半透明衬底、加过框、加过底纹，最后全被否掉（"歌词不要用衬底，看起来不太好看"）。参考片的解法是**改构图**：主体推到一侧，留一块本来就是黑的区域给字。可读性是**排出来的**，不是贴上去的。

### 1.8 字体分语域，而且是"按嗓门"排的

四个语域（`TREATMENT.md:24-29`）：

| 语域 | 字体 | 用途 |
|---|---|---|
| 人声 | **Archivo**（宽度轴 62–125、字重 300–900） | 歌词。又大又紧又自信；**按住长音时把字拉伸，受压时压窄** |
| 机器 | **IBM Plex Mono** | token、标签、HUD、表单、概率、脚注 |
| 神谕 | **Cormorant Garamond 斜体** | 极少用（Omega Point、"What did Ilya see?"） |
| 手写 | **单笔画笔式字体**（`stroke.ts`，8 种） | 被火花/绘图仪**写**出来的字 |

字号/字距：display 字常常占到画面宽的 1/3，字重 **800–900**，负字距；小字是等宽 13 px + 3 px 字距。

> 本片对照：歌词走 `dsSans(size, 200)`（Helvetica Neue **200 字重**）+ `track = 0.14em`（还很散），尺寸 46–84 px。**细字 + 散字距 + 小字号**，正是它看起来像"字幕/仪表读数"而不像"画面"的原因。

### 1.9 歌词 API 只暴露"每个词唱到哪了"

`lyrics.ts`：`wordProgress(word, t)`（0→1，音节级分段）、`lineCharProgress(line, t)`（已唱到第几个字，做逐字擦除）、`get('一句歌词片段')` 按**内容**找句（找不到就抛错，"写的时候要吵"）。

派生做法：`stroke.ts` 的 `writtenLength(st, charTimes, t)` 把"唱到哪"直接变成"笔写到哪"——**字是被唱出来的，也是被写出来的**，同一个时间轴。

### 1.10 世界内标注（in-world），不是角落 HUD

`ENGINE.md:71`：全局角落读数默认**关闭**（场景返回 `post.pdoom > 0` 才开）。P(doom) 这个数字在每个 plate 里用它**自己的语汇**露一次脸：等高线标签、示波器读数、表单字段、跑马灯、邮件里的一行……只有四个 hook 把它放大到全屏（`TREATMENT.md:43`）。

同一个仪表可以在任意位置画出来：`drawReadout(ctx, x, y, v, {scale})`。**一个数字，一种画法，位置和语汇随场景变。**

> 本片对照：**42 / 45 个镜头**都有四角遥测（左上 `c07 eye` 编号 + 右上数据表 + 读数 + 右下重复一句），等于每帧主动往四个角落各放一组等权重的"家具"——留白就是这么被吃掉的。

### 1.11 一个母题贯穿全片，而且几何是共享的

全片的线索是**火花和它拖出的线**：写下第一句歌词 → 画出 loss 曲线 → 变成股价 → 弯成第一个回形针 → 露出是导火索 → 最后引爆。它在大多数 plate 里出现（`TREATMENT.md:40`）。

面具（"助手微笑"）也只有一个定义：`_motifs.ts` 同时给出 Canvas2D 的 `drawMask2D` 和 GLSL 的 `sdMaskInk` 距离场，几何常量共用一份 `MASK`。**同一个东西在任何场景、任何渲染层里长得一模一样。**

### 1.12 22 个 plate、平均 6.8 s：节奏靠"镜头内"，不靠"切得碎"

时间线只有 22 条（`timeline.ts`），切点全部按歌词内容 + 拍网格算出来（`cut()` = 匹配句首词之前的最后一个拍；`after()` = 离句尾最近的强拍）。

镜头内部的节奏是**子切/重构图/甩镜/压字**，而且是**排好的、不是反应的**：拍网格在 `init()` 里算好，动作按 `beatsIn / cutBeat / timeOfBeat` 排期（`stack-kit.ts:177-192`），直接读 `f.a.kick` 的地方极少（全片一处）。

逐场数出来的量：每场 **2–17 次姿态变化，中位 ≈5**；长场里一个镜头 4–6 拍（1.8–3.6 s），快场里一个镜头 1 拍（`room.ts:650-654`；`bureau` 中位 0.7 s = 1.5 拍）。缓动是固定的四个动词：`outExpo` 到位、`outCubic/inOutCubic` 经过、`inQuart/inCubic` 离开、`outBack/springStep` 刹住；snap 0.09–0.22 s（`room.ts:739`），slam 0.14–0.16 s（`hook.ts:119`），whip 0.26–0.37 s（`leftturn.ts:213`）。**停顿是写进去的**（hook 在切点前 0.1 s 冻结，`hook.ts:195`）。
段落因此**互相独立又连贯**：时间线里没有切碎，画面里一直在动。

> 本片对照：47 个镜头 / 149.5 s = 平均 **3.2 s** 一刀，是它的两倍密度；而镜头内部几乎没有"姿态变化"这一层。**切得多 ≠ 有节奏。**

## 2. 它明确"不做"的事

风格圣经里逐条记录了**否决理由**（这是很值钱的一件事，见 §3 第 L 条）：

- 不画写实人眼/人脸（Revision 2 撤掉，因为"uncanny"）；面具是唯一的例外。
- 不用描边字/光晕字（`ENGINE.md:69`："No outlined or haloed type"）。
- 不要紫色/青色霓虹赛博朋克、发光大脑、Matrix 代码雨、镜头光晕汤、通用粒子星云、任何"一眼 AI"的图（`TREATMENT.md:12`）。
- 不用"每章一色"式的色相变化：撤掉了群青那一场（"读起来很诡异"）。
- 不要四角常驻读数、不要图注角标（Revision 2 全删）。
- 不套用现成作品的角色/logo（模型名只作为歌词文字出现）。

## 3. 可借鉴清单（按性价比排序）

> 每条：**借什么 → 为什么 → 落到 mv-kit 哪里**。"本片"= `projects/pdoom-ds`。

**A. 全片一套调色板，变奏改用"明度反转"** ★★★★★
借：9 键命名调色板（中性 5 + 信号 1 + 它的暗/亮 2 + 稀有强调 1），全书只允许一个信号色发光。
为什么：本片 4 套色相（ember/rose/ice/alert）让"变化"发生在最廉价的那个轴上，同时把"统一"丢掉了。
落地：`kits/lumen.js` 已有 `ice | ember | rose | alert | paper` 五套调色板——**别按章节换，改成全片一套（或 `x` + `paper` 两种底）**，章节差异交给体裁和曝光；`paper` 就是现成的"米白纸反转"。

**A2. 用足明度：黑要真黑，白要真白** ★★★★★
借：它有整幅米白纸的场景（平均亮度 0.86，88% 的像素是高光），深黑场平均亮度 0.06–0.33；全片高光占比 17%。
为什么：本片 19 帧均匀抽样里高光只占 **0.3%**，平均亮度 0.03–0.13，最亮一帧 0.33——**整片没有一场是亮的**。这是"看着闷"的物理原因，和配色无关；也解释了为什么"碎点"显得脏：没有亮部压住它们。
落地：① 至少两场把整幅翻成米白纸（`lumen` 的 `paper` 调色板 / `kits/print.js` 的纸底），平均亮度目标 0.7–0.9；② 深黑场让点云密处真烧到 1.0（现在最亮一帧平均只有 0.33）；③ `project.post.vignette` 别压中间调。

**B. 每个镜头声明一个主角，并给尺寸下限** ★★★★★
借："一帧一个能叫出名字的物件" + 大东西占画面面积下限。
为什么：本片每帧是"氛围场 + 家具"，没有落脚点（最大元素占比 12% vs 38%）。
落地：`TREATMENT.md` / `SHOTS.md` 的镜头表加一列 **HERO**（这一镜的主角是什么、占多大）；写代码时主角优先用**有轮廓/有体积**的形体（`lmPoints` 的高密度团、`LG` 线框、或者干脆是一块巨大的字），而不是一团均匀的尘。

**C. 砍掉四角遥测，改成"世界内读数"** ★★★★★
借：全局仪表默认关，P(doom) 每个 plate 用自己的语汇露一次脸，只有副歌把它放大到全屏。
为什么：本片 42/45 镜头四角都有遥测，把留白吃光了（见 `docs/refs/pdoom-ds-14-frames.png` 每格四个角）。
落地：`projects/*/lib/telemetry.js` 的 `dsTele` 从"每镜默认调一次"改成"每镜最多一处、位置贴着主角、语汇随场景"；副歌/高潮让同一个读数放大到全屏（本片 hook 已经这么做，把它变成常态）。

**D. 变化放在"体裁"，一章一个 kit** ★★★★☆
借：每个 plate 有自己的画法（版画/示波器/公文/钞票纹/蓝图/3D/织物/UI），共用一个调色板。
为什么：本片只用 `lumen` 一个 kit（45/45），却换了 4 套色——正好把两个轴都用反了。
落地：mv-kit 已经有现成的体裁库：`kits/print.js`（点阵打印）、`kits/ink.js`（水墨）、`kits/shadow.js`（皮影）、`kits/qinghua.js`（青花）、`kits/pigment.js`（颜料）、`kits/anime.js`、`lumen` 的 `paper` 反转。**A 组章节用 lumen，B 组章节用 print，C 组用 paper 反转**——色不换，画法换。

**E. 歌词的字重和字距，以及"宽度/字重动画"** ★★★★☆
借：display 字重 800–900 + 负字距 + 大字号；长音拉伸、受压压窄。
为什么：`dsSans(px, 200)` + `+0.14em` 是"细而散"，在大屏上就是字幕。
落地：`lib/lyric.js` 的默认 `dsSans(size, 200)` → 700–900（`projects/pdoom-akari/lib/fonts.js` 里 Zen Kaku Gothic New 有 700/900 两档，Dela Gothic One 是现成的重 display 面），`track: size*0.14` → 0 到负值。想做"宽度轴"动画，Canvas 2D 用 `g.scale(k, 1)` 就能压/拉字形（参考片是静态宽度实例 62–125 分档；我们不需要那么多档，2–3 档够）。

**F. 用构图给字让位（不改字，改镜头）** ★★★★☆
借：主体偏置，字落在本来就黑的区域；禁止垫底/描边/光晕。
为什么：本片的可读性问题是靠"加东西"解决的，加了又被否掉（衬底、框、底纹）。
落地：镜头表里每个有歌词的镜头写清 **字区**（哪块留黑）和 **主体区**；`check` 里"字离边缘 ≥96 px"的约定扩成"字区不得与主体重叠"。参考片还留了两个 HUD 专属角落：左下 360×140、右下 700×140。

**G. 歌词：treatment 已经够花了，缺的是"位置"和"体量"** ★★★★☆
先说公平的：本片 `lib/lyric.js` 的 `LY.plate` 表已经是参考片那套做法——46 行歌词逐行指定 treatment（carve 7 / terminal 6 / cloud 6 / wave 5 / scatter 5 / sweep 4 / slam 4 / ghost 4 / shock 3 / columnstack 2 / ascend 2，**12 种**），每行还写了理由，场景只写 `mode:'plate'`。这一条不用改。
真正没变的是：
- **位置**：46 行里 **43 行**落在画面下部的横带（`low` = 0.735H，22 行；`lower` = 0.855H，21 行）；`upper`（0.235H）**一次都没用过**；`centre` 只给 4 个 hook。`lib/lyric.js` 自己的注释写着"`low` 是字幕会用的那条带"——一针见血。
- **体量**：各模式的字号下限是 46–84 px（cloud 74 / carve 84 / wave 46 / scatter 62 / shock 70 / ghost 66 / ascend 60 / sweep 58），字重 `dsSans(size, 200)`。
参考片的字会**占满画面**（`SERVANT`、`BREAKING THROUGH`、`NVDA TO THE MOON`、`ALL THE…`），会出现在上三分之一，也会**贴在物体上**（沿曲线、沿导火索、印在钞票和表格上）。
落地：给 `LY.plate` 至少 8–10 行换到 `upper`/`centre`（非 hook）并把非 hook 模式的字号上限打开到 140–200 px；字尽量"贴到主角身上"（沿 `lmLines` 的曲线、沿物体的边缘），而不是永远平铺在画面下方。

**H. "被写出来"的字：把唱到的时间变成笔迹长度** ★★★☆☆
借：`writtenLength(st, charTimes, t)` —— 单笔画字体，字随唱到的字被写出来。
为什么：这是参考片里最"活"的歌词处理，且完全确定（纯函数）。
落地：mv-kit 没有 plotter 字体，但 `kits/ink.js` 的 `inkStroke(g, pts, w, {upto, taper, dry})` 已经能画"画到哪"的笔迹；用 `LY` 的逐字时间算 `upto`，配上书法/单线字形（`kits/ink.js` 的笔画 + `stroke` 思路）就能做同一件事。

**I. 4K = 逻辑分辨率 + 物理像素分离** ★★★★☆（工程）
借：场景永远按 1920×1080 逻辑坐标写（`W`/`H` 不变），引擎用 `SCALE` 放大；需要像素精度的量（发丝线宽、AA、超采样偏移）用 `pxLine` / `PX_SCALE` / `FRAG_PX` 换算；`Layer2D` 的 backing canvas 放大后把 ctx 预缩放。
为什么：上一版 4K 翻车的**根因**就是所有像素常量（字号、HUD 边距 44 px、14 px 标注、`LY_ZONE`）都写死在 1080p 画布上，改 `project.width` 就全崩。
落地：`docs/ENGINE.md` 加一节"逻辑分辨率"约定 + `mv.js` 暴露 `SCALE`/`PX`；项目里禁止出现裸的 1080/1920 常量（本片 `LY_ZONE` 已经踩过一次）。

**J. 自适应运动模糊（子帧数按帧收敛）** ★★★☆☆（工程）
借：每帧渲染多个子帧取平均，子帧数按"再翻一倍图像是否还变"自动升：4 → 12 → 36 → 108 → 324，判据是 2×2 逻辑像素块上最坏差值 < 3/255。
为什么：mv-kit 的 `--samples N` 是固定平均，静止帧白烧时间、快镜头又不够。参考片静止帧 12、普通运镜 36、甩镜/爆点 108–324。
落地：`tools/render.py` 的 `--samples auto`：先渲染 `n` 与 `2n` 两组子帧，比差值，收敛就停。注意本仓库的确定性规则（`render()` 只依赖 `f.t`）正好满足它的前提。

**K. 字幕式的"提前量"规则写进 API 注释** ★★★☆☆
借：允许整句提前 ≤0.4 s 淡淡显出，但高亮绝不抢拍（`TREATMENT.md:33`）。
落地：`lib/lyric.js` 的淡入默认已经接近；把它写成文档化常量，避免每个场景自己拍脑袋。

**L. 流程：风格圣经记录"否决理由"，引擎文档给场景作者立规矩** ★★★★★（方法）
借：
- `TREATMENT.md` 每次改版都写清楚**撤掉了什么、为什么**（写实眼睛=uncanny、群青=诡异、角标=多余、字底晕=不好看）。
- `ENGINE.md` 是"给场景作者的手册"：不能 `Math.random`；`render()` 必须整帧覆盖；`--only` 隔离单场渲染；**每改一个镜头就先渲 stills 然后用 Read 打开看图**；场景作者不许改引擎和时间线，需要什么就报告；性能预算 < 25 ms/帧。
为什么：本片这一轮里"加衬底→加框→换样式"来回三次，就是因为否决理由没有被写下来，同一类错会重犯。
落地：mv-kit 的 `CLAUDE.md` 已经有工作流，把这两条补进去即可：① 项目的 `TREATMENT.md` 维护 `## 已否决` 段；② `docs/ENGINE.md` 里加"场景作者须知"（隔离渲染、先看图、不许改工具）。

**M. 把"每场预算"写成硬约束** ★★★★☆（工程）
借：参考片 22 场里唯一从不变形的约束——全屏 pass ≤5、`LineBatch` ≤4、Canvas2D 层 ≤2、**同屏主角 1 个**、全片一套调色。
为什么：这是"看起来干净"的**结构性**来源，比任何美术手法都可靠；本片每个场景可以随手加层加特效加遥测，于是每帧都堆到"没有主角"。
落地：写进 `docs/ENGINE.md` 的"场景作者须知"，并在项目的 `TREATMENT.md` 镜头表里给每个镜头标 `HERO / 层数`；`tools/render.py check` 可以顺手统计每个场景用了几层（可选，但很便宜）。

## 5. 数据怎么来的（可复现）

```sh
# 从成片抽出和参考片同样时刻的 14 帧
for t in 7.5 14.3 27.4 31.9 44.4 63.95 73.3 84.3 100.2 104.5 113 117.6 127.9 133.6; do
  ffmpeg -v error -y -ss $t -i projects/pdoom-ds/out/AGI-·-P\(doom\).mp4 -frames:v 1 -vf scale=1280:-2 /tmp/mine/f$t.jpg
done

# 量尺（色相纪律 / 跨帧漂移 / 元素结构 / 墨量）
.venv/bin/python docs/refs/measure.py \
  '/Users/djj45/code/mv/pdoom-video/app/public/plates/fig*.jpg' \
  '/tmp/mine/f*.jpg'
```

参考片的那 14 帧就是它仓库里的 `app/public/plates/fig01–14.jpg`（由 `scripts/render.ts` 的 `plates` 模式生成，原本用于片尾倒带蒙太奇），所以是**片子自己的帧**，不是外链截图。注意这 14 张是 **HUD 关闭** 渲的。

§0 表里那些更强的数字（归一化边缘密度、纹理/墨覆盖、平坦区、粗细两种颗粒的元素数、池化色相瓣、高光与近黑占比）来自一次独立的全量审计：`docs/refs/audit/`。它对本片抽了 **19 帧全片均匀** 的样本（另外还用 125 张项目自带的剧照做了稳健性检验），在 960×540 与 1920×1080 两个尺度上各测一遍，并对"本片很暗、Sobel 有权重"这个混淆做了归一化处理。三个教训值得单独记住：

1. 抽帧方式会改变结论的量级——**同刻配对**（14 帧）适合比较"同一句歌词时两边在干什么"，**全片均匀**（19 帧）才适合说"全片有多少高光/多少颜色"。本片在参考片那 14 个时刻恰好落在青/品红场，配对抽样会把橙色的差距放大到 4.5%，而全片均匀抽样是 23–28%。
2. 原始 HSV 饱和度在不同亮度的片子上**不可比**（近黑像素的量化噪声会把暗片子的饱和度抬上去）；必须按曝光门控。
3. 参考片这 14 张剧照 HUD 关闭、本片带 HUD——这个不对称偏向参考片，而它仍然在结构量上领先，所以结论不会翻。

复核命令（只用本仓库的 venv）：`uv run --with numpy --with pillow --with scipy python docs/refs/audit/audit.py`；原始逐帧表 `docs/refs/audit/aggregates.csv`，完整报告 `docs/refs/audit/REPORT.md`，可视化 `docs/refs/audit/figure.png`。
