# 多轨审片与字幕 QA

`review` 针对已经导出的成片或 pilot 生成离线审片目录。默认播放 MP4 内的最终混音，画面也是实际编码结果；单轨试听复用 `out/.audio-cache/`。不重新执行 Canvas 渲染，不修改原 MP4 和回执。

```sh
uv run tools/render.py projects/recipe-demo review
# 打开命令输出的 out/review/<视频名>-<版本>/index.html
uv run tools/render.py projects/my-song review --file projects/my-song/out/pilots/sample.mp4
uv run tools/render.py projects/my-song subtitlecheck
```

默认目录包含 `index.html`、`review-notes.js`、成片副本、对齐 WAV、SRT/VTT、三份 QA JSON 和 `review.json`。可以整体搬走并用本地浏览器打开，不需要服务器、网络或外部字体；源媒体使用 H.264/AAC，浏览器需要支持这些格式。页面是一个版本快照，修改项目后需重新生成。已有目录不覆盖，可用 `--out` 指定新目录。

## 审看操作

- **成片混音**：直接播放 MP4 内的音轨，与交付文件一致。浏览器原来的 Canvas 预览仍播放 `project.audio`；这个入口用于审看最终结果。
- **单轨试听**：切换 BGM / 旁白 / 音效条目，播放器静音原 MP4，只播放对应 WAV。轨道已包含单轨增益、定位和淡化，未包含主混音限幅和首尾淡化；切回“成片混音”恢复最终音轨。单轨会跟随视频的播放、暂停、跳转和速度，但独立媒体时钟不作为逐帧音画证据，正式回测仍以成片为准。
- **字幕**：开关叠加导出字幕，点击字幕行跳转；重叠字幕同时展示。关闭叠加不会删除画面中已经绘制的歌词。叠加层用于核对文字与时机，不承诺其他剪辑软件的字体和布局一致。
- **定位**：点击有时间标记的 QA 项或镜头跳转并暂停；`−1 帧 / +1 帧` 用输出 FPS 计算步长。显示本片时间与原歌曲时间，样片不会错用原歌曲秒数去 seek。
- **结果**：默认列出 fail / warn / unverified，勾选后查看通过项和说明。没有可定位时间的全局检查只显示说明，不跳到任意帧。页面独立显示人工审片结论；自动 QA 不会替人填写结论。

生成 review 时复用 `filmcheck / sync / subtitlecheck`。项目或成片版本不匹配会拒绝生成；有可审查的编码/字幕问题时保留报告并生成页面，方便定位修复。`review` 退出码 0 表示页面生成成功，并非所有 QA 已通过。

音画事件可显式指定旁白或音效轨，检查消息会标明轨道 ID；`sync.json` 的 `audioReference` 包含源锚点、循环次数和实际输出时间映射。声明方式见 [ENCODED-QA.md](ENCODED-QA.md)，声音过弱或来源含糊时保留未验证。

## 人工审片记录

“人工审片记录”面板可填写审片人、整体备注和逐镜备注，并为每个镜头选择待复核 / 人工通过 / 需修改。点击镜头标题定位到该镜头。只有当前范围的全部镜头都标记为通过，才能把整体结论设为通过；之后任一镜头改为待复核或需修改，整体通过会自动撤回为待复核。自动 QA 面板保持原有状态。

草稿按完整版本分别存入浏览器本地存储，刷新后可恢复。浏览器拒绝存储时页面提示导出保存；可携带的正式记录是“导出审片记录”下载的 JSON，而不是浏览器草稿。整体搬移审片目录时也请保存导出的 JSON，再通过“导入记录”恢复。导入会替换同版本当前草稿，并保留操作前备份；旧版本或非法格式则拒绝导入，当前记录和已有备份都不变。需要保留多个审片人的意见时分别保存 JSON，当前版本不自动合并意见。

记录绑定渲染回执、成片、实际导出的单轨 / 混音 WAV 和 SRT / VTT 的完整内容摘要。只改声音或字幕也会产生不同绑定；旧记录不会自动成为新版通过结论。离线页面展示的是生成时的快照，修改工程后需重新生成审片页。

可用 `package --review-record /path/to/review-record.json` 随包保存匹配的人工结论；独立验包会继续核对版本和结论，见 [PACKAGE-VERIFY.md](PACKAGE-VERIFY.md)。审片人字段为手工填写，不是账户认证或数字签名。

## 导入、迁移与草稿恢复

成功导入同版本记录、迁入历史参考或移除问题前，会备份当前审片人、整体与逐镜备注、结论和历史参考。只保留最近一次操作前备份；下一次成功导入、迁移或移除问题会更新它，失败操作不会覆盖它。

- “撤销上次导入／迁移”恢复操作前的同版本草稿。恢复动作同时保留恢复前的状态，包括导入后继续填写的备注；按钮随后变为“恢复撤销前草稿”，可以找回这些内容。
- 恢复会整体替换草稿，不自动合并双方意见。迁移后的待复核结论仍按原规则生成；恢复只能取回本版本已存在的结论，不能把历史版本的通过结论迁进来。
- “导出操作前备份”输出普通审片 JSON，可通过同版本页面的普通导入恢复。正式审片导出与交付包只携带当前记录，不嵌入本地恢复槽。
- 当前正式草稿、一份备份和未提交问题编辑通过一次本地存储写入共同保存。正常情况下刷新后仍可恢复；存储被禁用或容量不足时，仅本次页面内保留最新草稿与备份，页面会明确提示刷新前分别导出。失败写入不会替换先前已存的草稿。
- 新页面能读取旧版单记录草稿，下一次保存时升级本地格式。旧离线页面不识别新的本地恢复格式，需要使用导出的正式审片 JSON 交换；没有时间标注的便携审片 JSON 仍兼容版本 1；包含时间标注或历史问题的记录使用版本 2，见下文。备份损坏或版本不符时禁用恢复，保留可验证的当前草稿。

## 时间标注与修改项

“时间标注与修改项”面板支持同一镜头的多个问题，状态独立于镜头整体结论：

1. 填写新问题说明，停在需要检查的位置，点击“记录当前帧”。
2. 需要一段范围时，分别点击“标记区间起点”和“标记终点（含当前帧）”，填写说明后点击“记录区间问题”。终点在起点之前时不能创建。
3. 点击已记录问题的时间按钮，暂停并跳到该帧，同时定位对应镜头备注。区间按钮定位起点，并显示终点；不会自动播放或自动通过。
4. 处理后填写处理说明，选择“已修改”并点击“保存问题处理”；实际复看后再选择“已复核”并保存。不能从待处理直接跳到已复核；已修改／已复核必须有处理说明。

时间以**输出视频的整数帧区间 `[startFrame,endFrame)`** 保存，点标注占一帧。界面显示输出秒数，歌曲时间为 `snapshot.origin + frame / fps`；标记终点会把当前帧包含进去，所以显示的结束秒数是下一帧边界。归属镜头用起始帧中心判断，转场重叠时归入时间线后面的镜头；跨镜头区间仍会影响覆盖范围内的所有镜头，未落入任何编码帧的极短镜头不计入影响。镜头间隙的问题保持无归属，不随意贴到邻镜。

新增待处理问题会将相关镜头设为需修改，并撤回已有的整片通过结论。待处理与已修改都属于未复核：相关镜头不能通过，整片也不能通过，包括镜头间隙中的问题。已复核问题不会自动把镜头或整片改为通过，仍要显式完成原有人工验收。这里没有账户或角色认证，处理和复核都是当前操作者的显式记录。

编辑问题说明会重新打开该问题；修改已复核项的处理说明会撤回到已修改（清空说明则回到待处理）。每行修改需点击“保存问题处理”才提交为正式记录。未提交编辑会作为独立缓冲自动写入本地草稿，筛选、翻页及正常刷新后可恢复；恢复只填充表单，不改变问题的正式状态。存在未提交行编辑时，导出当前记录、导入、迁移、恢复和移除问题会提示先保存或放弃，避免静默覆盖。普通逐镜备注仍按输入自动保存。

列表支持按待处理／已修改／已复核筛选，每页最多 20 条，每份记录最多 1000 条。误标可“移除问题”，操作前草稿进入现有单份备份槽，可撤销移除；移除也不会自动批准镜头。

### 未提交编辑恢复与问题导航

问题说明、处理说明和状态选择的未提交编辑，以及新问题说明和标记的区间，会与正式记录分开保存。刷新后继续编辑，不自动创建问题或提交处理状态。表单会同时显示正式状态和未提交提示；例如下拉框恢复为“已复核”，原正式状态仍是待处理，仍须经过原有处理／复核检查后显式保存。

本地草稿格式升级为版本 2，包含正式记录、单份备份和 `editor` 缓冲；旧的单记录与版本 1 本地草稿继续接受。编辑缓冲绑定完整成片版本，并保存其基于的正式问题内容；恢复时若对应问题已删除或被更新、缓冲格式非法或版本不符，则忽略不适用的缓冲并提示，保留可验证的正式记录。新问题区间按本版帧数校验，尚未完整标记或起终点顺序尚未修正的合法输入可继续编辑。

输入写入按 250 ms 窗口合并；离开输入焦点、页面隐藏或正常离开页面时尝试立即保存，提交处理、放弃编辑和恢复等操作立即写入。硬关闭进程或系统崩溃时，最后一个尚未写入的窗口仍可能丢失。存储被禁用或容量不足时会明确提示，旧的磁盘草稿不被覆盖；应先保存有效的问题处理并导出正式记录，无法提交的半成品文字请另行复制留存。

“放弃未提交编辑”会清除该行缓冲并保存清除结果；“清空新问题草稿”清空新问题文字和区间。正式审片导出与交付包不包含未提交缓冲，也不会把输入中的状态当作已完成的处理。

问题列表可组合使用：

- **搜索问题**：搜索正式问题说明、处理说明、问题 ID，以及涉及镜头的名称、场景、稳定 ID。未提交的表单文字不参与正式搜索。
- **只看当前镜头的问题**：包括该镜头覆盖到的跨镜头区间，不局限于问题起点归属。当前处于镜头间隙时列表为空；间隙问题仍可在全部问题中查找。
- **下一条待处理／下一条已修改待复核**：在本版全部正式问题中按起始帧时间顺序查找，末尾循环到开头；同一帧按记录顺序。导航清除问题搜索、状态及当前镜头筛选，跳转视频、镜头备注和目标问题所在页，并聚焦问题表单。无相应状态时禁用按钮。

列表本身保留记录顺序，每页仍最多 20 条；状态数量和导航均使用正式记录。未提交编辑在导航时保留。当前镜头筛选随播放或跳转更新，正在编辑或搜索时暂缓更新，避免抢走焦点；结束编辑后更新到当前镜头。筛选和导航不会替用户改变任何处理或批准状态。

### 记录、迁移和交付

新增时间标注后，审片记录升级为版本 2，顶层 `issues` 保存问题 ID、类型、帧范围、起始帧归属 `shotIndex`／稳定 `shotId`、说明、状态与处理说明。`snapshot` 同时携带输出 `fps`、`frames`、歌曲起点。旧的版本 1 记录继续接受；旧工具不能处理版本 2，需要升级，避免静默丢弃问题后误报通过。未使用时间标注的记录不强制升级。

跨版本迁移把旧问题保存到 `references[].issues`，附原始 `issueClock` 和可匹配的当前镜头索引。旧帧范围、处理说明与历史状态只读展示，不成为当前待办，也不继承已复核结论；镜头无法匹配时保留为未匹配参考。当前版本已有的问题保留。需要继续处理旧问题时，在当前画面重新标注其准确位置。

`package --review-record` 和独立验包都会保留并校验这些字段：检查帧范围、问题 ID、状态与处理说明、镜头归属，以及未复核问题和通过结论的冲突；还用包内真实渲染回执核对帧率、帧数、样片起点，不能只信记录自带的时间摘要。版本绑定、自动 QA 与人工结论仍保持原有规则。

## 长项目导航

逐镜表单每页最多显示 20 个，支持按镜头名称、场景或当前备注搜索，以及待复核 / 人工通过 / 需修改筛选。进度显示已复核数与各状态数量；“已复核”包含人工通过和需修改，不等同于全部通过。

- “下一条待复核”在整个当前样片范围内寻找下一条 `pending` 镜头，必要时循环到开头，并清除搜索、状态和变化筛选，定位画面和备注。需修改项可通过状态筛选单独处理。
- 当前播放镜头会高亮；重叠区间按时间线后出现的镜头归属，镜头间隙明确显示为空。
- “跟随播放翻页”只在当前镜头符合筛选条件时自动切页，不改动搜索与筛选。可以关闭跟随；“定位当前备注”会清除筛选并定位当前镜头。
- 输入备注、审片人或搜索条件时不自动换页抢走焦点。手动翻页、过滤或播放跳转都不会丢失已输入的草稿。

## 版本差异与参考迁移

新版导出的审片 JSON 附带 `snapshot`：当前范围的实际画面逐帧摘要、逐镜范围与画面摘要、音轨配置及导出 WAV 摘要、最终混音摘要和字幕内容。首次遇到一个视频流时解码计算摘要，后续通过画面摘要缓存复用，不保存原始帧。混音或字幕修改不会仅因 MP4 文件整体摘要变化而被误报为画面变化。

在“版本比较与历史参考”中上传另一版本的审片 JSON，先查看差异，再点击“迁入参考并重新复核”：

- 镜头优先按持久 `shot.id` 关联，支持重命名、场景替换和重排。缺少 ID 时，才退回两个版本中均唯一的“名称＋场景”；两边都有 ID 且不同，即使同名也不关联。列出画面、时间范围、名称、场景变化，以及新增、移除和匹配不唯一。
- 镜头摘要覆盖该镜头在成片中的合成画面，包含转场。转场重叠区域变化时，相关镜头可能都被标记。像素或色彩显示参数变化会触发画面变化提示。
- 音轨按轨道 ID 比较实际导出 WAV 与 cue 配置，同时独立比较最终混音。字幕按实际导出文本和时间比较，修改表现为旧条目移除、新条目加入。
- 当前备注和当前审片人保留，旧备注以带来源版本、审片人信息的只读参考展示；**全部逐镜结论及整体结论重置为待复核**，包括画面未变的镜头。
- 已移除、重名或无法关联的镜头备注进入“未匹配参考”，不丢弃、不贴到同序号的新镜头。重复迁入同一来源版本不重复叠加；更早的历史参考也会继续保留并重新映射。
- 第十批及更早的 JSON 没有差异摘要：仍可迁入整体意见及未匹配逐镜参考，但不能据此判断哪些媒体发生变化，也不自动关联逐镜备注。

普通“导入记录”仍只接受完整版本匹配的记录；版本不同必须走显式比较与参考迁移。即使可见画面、音轨和字幕都相同，回执或其他依赖变化仍可能令完整版本不同，旧通过结论不会自动沿用。

历史参考记录在 `references` 中，最多保留 50 个来源版本。参考与比较摘要会随 JSON 导出、同版本重新导入及 `package --review-record` 一并保留，独立验包也检查格式和当前镜头目标。差异依据是旧记录携带的摘要，不是对旧媒体重新验包，也不是数字签名；自动 QA 和人工结论仍保持独立。

## 差异定位与变化镜头筛选

比较带差异摘要的历史 JSON 后，变化镜头和可定位的字幕条目会显示为按钮。点击后暂停播放、跳到当前成片对应时间，并翻到对应镜头备注；“上一处变化／下一处变化”按当前成片时间顺序循环。相同时间的多项差异分别保留，位置提示显示当前项与总数。

“只看变化镜头（含字幕涉及镜头）”包括画面、时间范围、名称、场景的变化及新增／匹配不唯一的当前镜头，也包括可定位字幕差异覆盖的镜头；它可与搜索、状态筛选叠加。字幕跨镜头或处于转场重叠时，相关镜头都会纳入筛选。点击差异定位会清除搜索与状态筛选，保留适用的变化筛选，确保对应备注可见；不会改动审片结论。播放与填写备注的焦点保护继续生效。

新增字幕使用当前成片时间；旧字幕移除项先按“旧样片起点＋旧字幕时间－当前样片起点”转换位置，再检查是否落在当前范围。旧记录缺少起点、位置超出当前范围、已移除或无唯一映射的历史镜头，只显示说明，不跳到任意帧。字幕位于镜头间隙时仅定位视频并说明没有逐镜备注。音轨差异目前仍是整轨提示，没有声称定位到具体变化时刻。

比较对象仅在本次页面内使用；刷新后需重新选择历史 JSON。切换比较对象、导入非法比较记录时，会清除上次定位目标和变化筛选，防止沿用失效位置。没有差异摘要的旧记录仍可迁入参考，但不启用变化定位。

## 画面摘要缓存与稳定镜头 ID

`review` 将解码后的逐帧 SHA-256 摘要存入 `out/.review-cache/`，只用于版本差异，不替代成片、音画或字幕 QA。每次都重新读取实际视频包，复用逐镜交付已有的视频流身份算法，包含包时间、编码附加数据和显示参数；不按文件名、大小或修改时间认定命中。缓存键还包括输出规格、帧数、FFmpeg 版本和处理代码版本。

重复生成审片页、只改 sidecar 字幕，以及 `remix` 保持视频流不变时，可以命中同一份摘要。命中避免版本比较所需的额外像素解码；正常 QA、视频包扫描、文件完整性检查和离线媒体复制仍会执行，因此不承诺整个审片过程零解码或固定倍数提速。逐镜摘要按本次回执的镜头时间范围重新汇总，缓存不会锁住旧镜头划分。

缓存带内容摘要、结构和帧数检查；损坏或缺失时重建。复用现有进程锁、命中统计、原子发布及预览清理流程；并发只构建一次，中断不会发布半份缓存。`review.json` 中的 `pictureCache` 和命令日志说明本次是否命中，它们不参与人工结论绑定。

```sh
uv run tools/cachectl.py projects/recipe-demo --kind review
uv run tools/cachectl.py projects/recipe-demo --kind review --prune --older-than-days 7
# 确认预览范围后，添加 --apply 执行同一清理策略
```

时间线中可选写入稳定 ID：

```js
{ id: 'opening.route', scene: 'path', name: '路线展开', from: T0, to: beat(8) }
```

ID 长度为 1–128 个字符，以英文字母或数字开头，后续允许字母、数字、`.`、`_`、`:`、`-`，在整个有效时间线中唯一，与 `sync` 事件 ID 分属不同用途。名称、场景或位置变化时保留 ID；复制出一个独立镜头时分配新 ID，不用镜头序号生成会随重排变化的 ID。拆分或合并时为新镜头分配新 ID，旧备注保留为未匹配参考；系统不猜一对多或多对一关系。

ID 会进入导出信息、渲染回执、审片快照和交付包内记录。非法或重复 ID 会阻止导出；审片导入也检查 ID。没有 ID 的旧项目无需补字段，旧快照继续按唯一名称与场景匹配；一边开始采用 ID 时也可沿用此兼容匹配，但同次改名无法凭空恢复旧身份。

给现有时间线添加 ID 仍属于项目依赖变化，需按现有规则正常导出一次，不能直接修改旧回执或用 `remix` 跳过。ID 仅帮助关联历史参考，不继承任何旧版通过结论。

## 字幕检查规则

字幕导出、审片叠加和 QA 共用同一份裁剪、归零、毫秒取整、空行整理逻辑。检查的是当前导出范围内实际留下的字幕，包含因样片边界裁剪变得过短的条目。

在 `project.js` 用可选的 `subtitleQa` 设置提示阈值：

```json
"subtitleQa": {
  "minDuration": 0.8,
  "maxCps": 20,
  "maxLineWidth": 42,
  "maxLines": 2
}
```

这些是本项目的默认启发式阈值，可按语言与用途调整，不是字幕行业合规标准。

| 检查 | 说明 |
|---|---|
| 停留时间 | 导出后短于 `minDuration` 秒 |
| 阅读速度 | 每秒非空白字符数超过 `maxCps`；组合音标和控制字符不重复计数 |
| 过长行 | 超过 `maxLineWidth` 列；中日韩等宽字符计 2 列，普通字符计 1 列 |
| 行数 | 超过 `maxLines` |
| 时间重叠 | 新字幕在上一条仍显示时出现，包括嵌套重叠；相邻边界不算重叠 |
| 毫秒取整 | 在输出范围内、却因过短而在导出取整后消失 |

可读性问题是 `warn`，方便双语字幕、短提示音标签等人工复核；非法配置、错误时间或空文本为 `fail`。当前范围没有字幕会明确标注未评估可读性。这里不做语音识别、文意校对或旁白字词对齐，也不替代原有 Canvas 歌词/画面 QA。

`subtitlecheck` 报告存入 `out/qa/encoded/<视频标识>/subtitles.json` 和 `.md`，含 cue 编号、本片秒数、原歌曲秒数、输出帧及阈值。退出码沿用现有规则：通过/警告为 0、失败为 1、证据不足为 2。`video / pilot / remix --verify` 同时执行三类检查；`package` 也携带 `subtitles.json`。

只修改 sidecar 字幕后，先运行 `subtitles` 刷新回执，再 `review`。修改已经画入画面的歌词，仍需正常渲染。修改 `project.subtitleQa` 属于项目配置变化，按现有版本规则需先正常导出。
