# B 站投稿备忘

## 成片：投 1080P 那版

| 文件 | 规格 | 说明 |
|---|---|---|
| `projects/pdoom-ds/out/AGI-·-P(doom).mp4` | 1920×1080 30fps, CRF 18, **8.3 Mbps** | **推荐投稿**。B 站 1080P 档推荐 6 Mbps，这条已经更足；构图是原始设计 |
| `projects/pdoom-ds-4k/out/AGI-4K-upscaled.mp4` | 3840×2160 30fps, CRF 16, **28.7 Mbps** | 用 1080P 母版 Lanczos 放大而来，构图与 1080P 逐像素一致（缩回后差 0.2–0.8，编码噪声级） |

**为什么推荐 1080P**：这部影片的画面是在 1920×1080 的画布上画的，场景和库里的像素量都是
按 1080p 定的（歌词字号、仪表字号、HUD 边距 44px、14px 标注……）。所以片子**本身没有 4K 细节
可以采**——真要在 3840×2160 画布上渲，这些定值不会跟着放大，画面比例会变（我试过，同一时刻
亮部占比 42.3% vs 56.0%，构图确实不同，那版已删掉）。放大版只是把同一张画放进 4K 容器：
分镜、构图、每一根线都和 1080P 一样，只是没有额外的真实细节。

投稿建议：**用 1080P 那版**。它码率足够高（是推荐值的 1.4 倍），B 站转码后 1080P 会很干净；
如果投稿位支持 4K 并且你想要那个"4K"标，再用放大版。

## 标题 / 简介草稿

标题：`AGI · P(doom)｜整支 MV 没有一帧是画出来的`

简介：
```
一支完全由代码绘制的 MV：点云、发丝线、Canvas 2D 字体，没有用任何生图或生视频模型。
每一帧都只是歌曲时间 t 的函数——同一个 t 永远给出同一帧，所以预览、截图和成片逐像素一致。
47 个镜头，每一次切点都落在小节头或某个字被唱出的那一瞬。

四次副歌不是同一段兼用卡：按 AGI 的程度分四个阶段——EMERGENT（字一直没稳定下来）、
NESTED（字后面还有一层）、PARALLEL（字裂开又拼合）、RESOLVED（不动了，因为没什么要证明的）。
歌词有九种形态，其中一句是从画面里"挖"出来的。

制作笔记（分镜、配色、歌词形态、四个阶段）在项目的 README / TREATMENT 里。
```

标签建议：`MV` `AGI` `代码绘画` `创意编程` `WebGL` `音乐可视化` `pdoom`
