# 镜头配方练习 · 制作与验收

目的：用最少的图形解释五种动作时序，给新项目可复制的代码。固定色板、系统无衬线字体、无外部素材；不是歌词 MV，歌词可读性需在真实歌曲项目里另验。镜头表见 README，配方动作与参数见 `recipes/`。

代表性样片：18–23 秒，`portal → arrival`，在 20 秒重拍附近完成圆形尺度匹配。旧镜头延续至 20.3 秒以覆盖转场；新镜头保留稳定轮廓与内部运动。转场两侧使用同一讲解文字，避免不同标题在叠化时重影。正式样片路径 `out/pilots/pilot-00018.000-00023.000.mp4`。

## 保留的 QA 警告

示例全片 QA 为 0 错误、4 个 `static` 警告。没有关闭检查或修改阈值；检查的是稀疏练习图形的全屏变化占比，以下保留有意的停留，不为消警告加入无关运动：

| 镜头 | 原因与检查重点 |
|---|---|
| path | 细线与端点占画面很少；第 5 拍完成后保持结果。检查端点确实前进、路径不回退，真实复杂画面不能照搬这个占比判断。 |
| steps | 数字和细条变化面积小，两个事件之间刻意保持数值。检查每次跳变及平台期，不能把数值一直滚动当作改进。 |
| portal | 大圆位置稳定，只有轨道标记运动，为后续同形转场建立视觉锚点。`push:0` 保持锚点精确；需连同转场一起看。 |
| arrival | 圆形轮廓保持，小圆点旋转的变化面积低于静止阈值。新空间的阅读停留是目的；须用连续帧确认小圆点运动，没有冻结。 |

已核对首 / 中 / 尾拼板、转场连续帧及成片流信息；工具检查不等同于人工完整带声审看。样片 JSON 的审看状态保留 pending，使用者可带声播放后记录节奏感受。

## 编码后检查与音画回测

全片和 3–9 秒样片通过实际 MP4 解码检查规格、帧数和音轨。三个时间线事件 `steps-enter`（4 秒）、`value-change`（5 秒）、`assembly-enter`（8 秒）均有可靠波形与画面变化峰，实测画面减声音误差为 0 帧；5 秒测的是数字开始变化附近的峰，不是数字最终稳定时刻。

全片 `filmcheck` 保留 3 个 `freeze` 警告：0–1.5 秒的细线、16–19.5 秒的圆形引导、20.458–24 秒的小圆点运动。在 320 像素宽扫描中变化面积太小，达到近静止判据；前述拼板与连续帧可见细节运动，保留稀疏练习设计并记录原因，没有关闭检测。3–9 秒样片的 `filmcheck / sync` 都为 `pass`。完整报告保存在 `out/qa/encoded/`。

默认 18–23 秒平滑转场样片没有声明可自动测量的语义落点，音画结果应是 `unverified`，不可借用另一段的通过结果。上述自动检查不替代完整带声审看。
