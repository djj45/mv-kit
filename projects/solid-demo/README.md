# solid-demo — 样张：kits/solid.js + kits/sim.js

不是 MV（没有歌：歌词是占位的原创句子，节拍是 120 BPM 的网格），是接在 lumen.js 上的两个新风格包的示范。三个镜头，每个演示一样 lumen 本来画不了的东西：

| 时间 | 镜头 | 调色板 | 演示 |
|---|---|---|---|
| 0–6 s | `glass` | rose | **受光的面**：Taubin 心形曲面（`SG.implicit`，行进四面体，约 27 万个三角形）做成玻璃（`smGlass`），在拍子上"扑通"跳两下、小节头那一下最重（玻璃一弯，颜色裂开）；后面的光点墙和光条透过它被折射、红蓝分开；唱到 "inside" 时里面亮起一团光核；一圈粒子环穿过玻璃转——后面那一半被折射，前面那一半清楚（`occlude: 'behind' / 'front'`）。曲面上的等高线是 `bands` |
| 6–12 s | `lattice` | ice | **全屏着色器**：光线步进的晶格巨构（`smShader`，`sdBoxFrame` × 无限重复，一些格子里套小框、少数格子亮着一块面板）。一开始是暗的，格子从近到远一格格通电；然后镜头每拍冲进一间（快冲、停住），每个小节头一道光沿走廊往前跑。着色器写深度，lumen 的探针（线框小方块 + 光核）和尘埃会被框挡住。歌词区那一块结构自己暗下去（`uQuiet`） |
| 12–18 s | `sand` | ember | **模拟**：一百万粒沙在一块金属板上（板是 `smMesh` 的高度场，振动时高光闪动）。唱到 "shake" 板响起来，沙从振动的地方跳开、落到不动的节线上，排成这个振型的克拉尼图形 u = cos(nπx)cos(mπz) ± cos(mπx)cos(nπz)；每个小节头换一个音，沙跳起来重新排成更细的线。沙是真的模拟（每粒沙跳的幅度和它脚下板的振幅成正比，再顺着 u² 的坡往下漂），通过 `SIM.make` 跑，所以每一帧仍然只由 t 决定 |

```sh
open projects/solid-demo/index.html
uv run tools/render.py projects/solid-demo sheet --cuts
uv run tools/render.py projects/solid-demo
```

## 做的时候踩到的坑（写新镜头时照着避开）

- **隐式曲面要一个梯度不为零的写法**。Taubin 心形的标准式是 A³ − B³ = 0（A = x² + 9/4 z² + y² − 1，B = y·∛(x² + 9/80 z²)），它在腰线（y = 0）上梯度为零，法线是乱的，玻璃上会出现一条横着的接缝；先开立方根也不行（梯度在曲面上变成无穷大，折射出一圈圈台阶）。因为 A³ − B³ = (A − B)(A² + AB + B²)，同一个曲面就是 A − B = 0，用这个建网格，法线处处光滑。
- **玻璃要有东西可折射**。纯黑背景前的玻璃只剩边光，看不出是玻璃；直的光条、规则的点阵最能显出"弯"。背景亮一点，玻璃本身的染色（`tintK`）和内边缘光（`glow`）压低，不然像一个粉色气球。
- **光线步进的细线要算像素宽**。相机在格子中心时最近的框边离它只有一个单位，0.011 的边厚在 62° 视角下是二十个像素；0.0045 才是细线。格子不要全满（留一些空格，暗处才显得深），并且步长不要越过格壁（`min(d, wall + 0.02)`），否则邻格的框会被跳过、出现破洞。
- **百万点要分清"铺满"和"成线"**。一百万粒沙均匀铺在板上时每个像素一两粒，`gain` 高了整块板就是一张白纸；压到 0.085，均匀时是灰色的沙面，聚到节线上（密十几倍）才烧成白线。
- **qa 的 `one-speed`**：点阵闪烁、粒子环一直转，每 1/6 秒画面都变一样多，事件就不突出。背景静下来，让事件（光核亮起、小节头的重拍）去动。

## qa 和速度

- 三个镜头分别跑 `qa --from … --to …`：0 错误、0 警告。整片跑时会多出 `type-flat / type-band` 两条警告：全片只用了一种歌词（左下终端，30 px），这是样张有意的——lumen 的 README 建议一支片子里二选一贯穿（终端或底部字幕）。正式的 MV 里在副歌用大字、拆字或粒子拼字把字号拉开。
- 在没有 GPU 的软件渲染（SwiftShader，2 核云端机器）上：玻璃约 1.5 s / 帧，光线步进的晶格约 5 s / 帧，百万沙粒约 20 s / 帧（大头是一百万个点精灵的光栅化，不是模拟：模拟一步约 20 ms）。在 Mac 的 GPU 上这些都是几十毫秒的量级；光线步进的步数（120）和沙粒数可以按机器调。
- 预览（`index.html`）里沙子那一镜每帧要往前算两步模拟，实时播放会掉到十几帧；往回拖时回到最近的检查点（每 0.5 s 一份，每份 12 MB）再往前算。

## 写 TREATMENT 时可以照抄的画风要点

- **规则**：lumen 的"一切都是光"不变——黑底、叠加、泛光；面只在需要"摸得到"的时候出现（玻璃、金属、分子、立体字），而且面也是用光画的：暗的本体 + 亮的边光和高光，几乎没有漫反射的灰面。
- **玻璃**：边光细而亮，高光是小块的窗形（摄影棚的柔光箱），折射出背景的直线，色散只在边缘看得见；里面放一个发光的东西，玻璃就有了"里面"。
- **结构**：光线步进的空间要有尺度感——近处的细框、远处被雾吞掉的格子、偶尔一块亮面板；镜头在里面穿行时要有快有停（每拍冲一下），一直匀速就是屏保。
- **模拟**：先让观众看到"静止的初始状态"（铺满的沙），再给一个原因（板响了），然后让结果自己长出来（线），每一步落在拍上。数字（粒子数、振型、步数）放进 HUD，让观众知道这是算出来的。
